Assessments

Assessment mirrors the course loop: spec → AI proposal → human critique → tests/measurement → keep or improve. Homeworks are AI-heavy and graded on how you steer, constrain, test, and critique AI; quizzes are AI-free and test the mental models behind that work.

Homeworks 60% · Quizzes 40%. The two halves are deliberately in tension. You are expected to use AI heavily on the homeworks — and the quizzes measure what you understood while doing so. Using AI to learn produces a good quiz score; using it to copy does not. That is why the quizzes carry 40%: it is enough that copying your way through the homeworks cannot be recovered from. The syllabus Canvas ↗ is authoritative if these figures ever disagree with it.

Six Homeworks (roughly biweekly)

Each is a mini-project: AI-generated code + student-designed tests + a written reflection + a completed AI-disclosure dossier + your AI session transcripts. Submission is by push to your GitHub Classroom repo (push = submit) — see the git workflow.

Every homework is graded by the same five categories — the homework rubric. Read it before you start HW1; it is the only document that defines what “graded on how you steer AI” means in points.

Scoring

Questions are not worth the same. The 22 questions are worth 33 points: 14 recall questions at 1 point, 5 short-code questions at 2, and 3 multi-step traces at 3.

Full credit is 30 of 33 points. Three points are forgiven, so a couple of mistakes cost nothing — the allowance exists so that an unclear or defective question cannot hurt you. Below 30, the grade is proportional. Try the score calculator →

If a quiz proves harder than intended, grades are adjusted upward afterwards. They are never adjusted down.

Scope

Quizzes draw only on material presented in the slides (where provided) and the assigned demonstration pages for the modules being covered — including the self-study demos, which are not taught in class but are examinable exactly like the rest. Nothing outside that scope appears.

Three qualifications:

  • Questions ask what C++ guarantees, not what one compiler does. Where a program’s behaviour is undefined or implementation-defined, that is the answer — never a particular value your machine happened to print. You will not be asked to recall an exit code, a sanitizer’s exact message, or one compiler’s wording of a diagnostic. Answers hold on every platform, or they are not asked.
  • Quizzes are cumulative. Each quiz centres on the modules listed above, but the course builds on itself, so earlier material — including earlier agentic material — remains fair game throughout.
  • Roughly 30% of the questions cover the agentic material. The AI-facing demonstrations are examinable exactly as the C++ ones are, in every quiz, starting with Quiz 1.

Attendance and missed quizzes

  • There is no penalty for guessing. Never leave a question blank.
  • Quiz 4 is on Tuesday Nov. 24, a normal class day. Thanksgiving break is Nov. 25–27.
  • A quiz missed with an excuse arranged in advance, or documented afterwards by a doctor’s note, is dropped; your remaining quizzes carry the full weight. An unexcused absence scores zero.
  • At most one quiz can be dropped. If you miss a second, the remedy is a 10-minute oral quiz in office hours — five questions, same material — rather than a second drop, because three quizzes are not enough to assess a course worth 40% of your grade.

Only format and schedule are published here; the items themselves are handed out on paper in class.

AI transcripts

Every AI session you run while working on a homework is submitted with that homework. Not a selection, not the interesting parts — all of them.

What to submit

  • All sessions. One file per session. If you opened five conversations across two weeks, you submit five files.
  • Markdown, plain text. Strip the JSON; the readable conversation is what matters.
  • Timestamped filenames, using the session’s start time: 2026-09-03_14h05mEST.md. Sorting the directory should reconstruct the order you worked in.
  • In your homework repo, in a top-level transcripts/ directory. Pushing is submitting — see the git workflow.
hw2/
  src/
  tests/
  DOSSIER.md
  transcripts/
    2026-09-14_09h12mEST.md
    2026-09-14_21h40mEST.md
    2026-09-16_11h03mEST.md

If you wrote part of the assignment without AI, nothing needs to be submitted for that part — say so in the dossier.

Homework rubric

Every homework is graded by the same five categories, in the same proportions. They are published because you have almost certainly never been graded on this before: not on whether you wrote the code, but on whether you specified, verified, critiqued, and disclosed work that an AI largely produced.

The vocabulary here is not new. It is the vocabulary of the course — a prompt is a spec, green is a property of the tests, the four gates in cost order — used as a grading instrument.

AI-Disclosure Dossier

Every homework ships a dossier — a short, fixed-form disclosure of how you used AI. It does two jobs: it keeps grading fast, and it makes your AI use visible and accountable (which models, what you asked, roughly what it cost, and at least one non-trivial mistake you caught).

How it is graded

Two passes, and the first is mechanical:

  1. Run ./check_dossier.sh DOSSIER.md (or DOSSIER_LITE.md) in your repo. Red = the dossier is ungraded, full stop — it enforces the form and the length caps.
  2. Green → the grader reads your reasoning: does the named mistake cite real evidence (a probe value, a diagnostic, a failing test) rather than vibes?

You run the same checker the grader runs — check_dossier.sh ships in every starter repo.

Demo Library

Agentic demos (12)
  • ag_context The model answers the context, not the prompt; the context inventory.
  • ag_diff Review the change not the file: regression/feature halves, edge table.
  • ag_evidence The four-gate evidence ladder (compiles/runs/battery/ASan).
  • ag_explain Explanations are unverified commitments; check them against the run.
  • ag_grounding Ungrounded vs grounded (real header pasted in).
  • ag_hallucination The compiler as first honesty gate: invented refs, stale APIs.
  • ag_models Same prompt x six local tiers x three frameworks; which gate stops each.
  • ag_numverify Numerically-wrong-but-green; cancellation; the oracle is part of the test.
  • ag_pipeline The first agentic pipeline as a recorded replay: build/test/feedback loop.
  • ag_repair Directing a repair: vague vs directed, what-must-not-change clauses.
  • ag_testgate Same code, weak vs strong battery; green is a property of the tests.
  • agentic_spec Vague prompt vs spec-grade prompt; a prompt is a specification.
Foundations (13)
  • array_pointer Array-to-pointer decay, std::array/span, off-the-end pointer.
  • benchmarking Timing done right; the optimizer deletes your benchmark; cache effects.
  • compile_time if constexpr, SFINAE/enable_if, concepts, static_assert.
  • debugging Reading a sanitizer report; assert vs exception vs silent; UB.
  • function_args Pass by value/pointer/reference, const&, move, RVO.
  • list_ops Linked-list pointer mechanics: insert/erase/splice, iterator validity.
  • numerics Floating-point behavior: tolerances, cancellation, abs vs rel error.
  • ownership The four ownership relationships; RAII enforces ownership.
  • pointers_basic References vs pointers, nullptr, dangling/null gotchas.
  • smart_pointers unique/shared/weak_ptr, make_*, ownership and double-free.
  • stackframes Stack vs heap vs static lifetime; recursion frames.
  • strings std::string value semantics, SSO, string_view borrowing and dangle.
  • type_deduction auto drops ref/const, range-for copy mistake, decltype(auto).
OOP (12)
  • class_structure Buffer anchor: ctors, deep vs shallow copy (ASan), move ops, dtor.
  • custom_iterators A minimal forward iterator that works with STL algorithms.
  • custom_types Hashable/comparable/movable/streamable value types; explicit ctors.
  • exceptions throw/try/catch, catch-by-ref, RAII unwinding, noexcept.
  • functional Four callables under one signature; std::function type erasure.
  • inheritance is-a, virtual dispatch, slicing, override, non-virtual-dtor gotcha.
  • lambdas Capture by value/ref, mutable, predicates, dangling-capture gotcha.
  • nested_containers Matrix as vector-of-vectors / flat / sparse (map vs CSR).
  • op_overload Vec2 anchor: arithmetic, comparison, iostream, const-correctness.
  • stl Containers, iterators, algorithms-over-loops, iterator invalidation.
  • templates Type params, deduction, specialization, header-visibility gotcha, CTAD.
  • testing Writing a C++ test: boundary/value tests, tolerances, regression.
