Linked List Operations

Main Takeaway

std::list is a doubly-linked chain of separately-allocated nodes. Its O(1) insert and erase at any iterator position — and the guarantee that no operation invalidates existing iterators except an erase of that exact node — follow directly from its structure. This module shows how those operations work and where they differ from std::vector.

▸Key Idea

Each push_back appends one node to the list. Hover (or tab to) a "pushed N" line, the code that printed it, or the node in the diagram — all three light up together, so you can see exactly which line built which node.

#include <iostream> #include <list> int main() { std::list<int> lst; lst.push_back(5); std::cout << "pushed 5\n"; lst.push_back(2); std::cout << "pushed 2\n"; lst.push_back(9); std::cout << "pushed 9\n"; }
Program output
pushed 5 pushed 2 pushed 9

list = {5, 2, 9} — each node built by its push_back line

▸Key Idea

std::list provides O(1) insertion anywhere: push_front and push_back at the ends, and insert(it, val) to place a new node just before iterator it — without moving any existing node. insert returns an iterator to the new element. Every other iterator remains valid after the operation.

#include <iostream>
#include <list>
int main() {
    std::list<int> lst = {5, 2, 9, 1, 7};
    lst.push_front(0);
    std::cout << "after push_front(0):";
    for (int x : lst) std::cout << " " << x;
    std::cout << "\n";
}

▸Key Idea

list::erase(it) removes the node at it and returns an iterator to the next element — the key to safe in-loop erasure. Unlike vector::erase, no other node moves and no other iterator is invalidated. erase(first, last) removes the half-open range [first, last) in O(n) steps.

#include <iostream> #include <list> #include <algorithm> int main() { std::list<int> lst = {5, 2, 9, 1, 7}; auto it = std::find(lst.begin(), lst.end(), 9); // EXPECT: node 9 is removed; erase returns an iterator to the next node (1) // after the call: lst = {5, 2, 1, 7} (only node 9 unlinked and freed) auto next = lst.erase(it); std::cout << "next after erased 9: " << *next << "\n"; std::cout << "after erase(9):"; for (int x : lst) std::cout << " " << x; std::cout << "\n"; }
Program output
next after erased 9: 1 after erase(9): 5 2 1 7

before — list = {5, 2, 9, 1, 7}. erase(it) where *it == 9 (highlighted) — its neighbors are node 2 and node 1

node2.next → node1 AND node1.prev → node2 — 9 is now unlinked (2 writes, O(1))

node 9 freed — erase returns an iterator to node 1. after — list = {5, 2, 1, 7}; no other node moved, no other iterator invalidated

#include <iostream>
#include <list>
int main() {
    std::list<int> lst = {5, 2, 9, 1, 7, 4, 6};
    // erase returns the next valid iterator -- safe to continue the loop
    for (auto it = lst.begin(); it != lst.end(); ) {
        if (*it % 2 == 0)
            it = lst.erase(it);
        else
            ++it;
    }
    std::cout << "odd elements only:";
    for (int x : lst) std::cout << " " << x;
    std::cout << "\n";
}

▸Key Idea

list::splice moves nodes between lists (or within one list) in O(1): no elements are copied or allocated — only a constant number of pointer rewrites happen, regardless of the range length. std::vector has no equivalent because its contiguous layout makes any transfer O(n). All iterators to the spliced nodes remain valid; they now belong to the destination list.

#include <iostream> #include <list> int main() { std::list<int> b = {10, 20}; std::list<int> c = {2, 9}; // EXPECT: the ENTIRE list c moves to the end of b; c becomes empty // after the call: b = {10, 20, 2, 9}, c = {} (moved, not copied) b.splice(b.end(), c); std::cout << "b after splice:"; for (int x : b) std::cout << " " << x; std::cout << "\n"; std::cout << "c size after splice: " << c.size() << "\n"; }
Program output
b after splice: 10 20 2 9 c size after splice: 0

before — list b = {10, 20}, list c = {2, 9}. splice(b.end(), c) moves the ENTIRE list c to the end of b — no first/last needed. c will become empty

list c gives up every node at once — c is now empty. The 2⇄9 chain travels as one unit, internal link intact

link c's chain after 20: node20.next → node2. after — list b = {10, 20, 2, 9}, list c = {} (empty). moved, not copied

#include <iostream> #include <list> #include <algorithm> int main() { std::list<int> a = {5, 2, 9}; std::list<int> b = {10, 20}; // src refers to node 2 in list a; dst refers to node 20 in list b auto src = std::find(a.begin(), a.end(), 2); auto dst = std::find(b.begin(), b.end(), 20); // EXPECT: node 2 moves out of a and is re-linked into b, just before 20 // after the call: a = {5, 9}, b = {10, 2, 20} (moved, not copied) b.splice(dst, a, src); std::cout << "a after splice:"; for (int x : a) std::cout << " " << x; std::cout << "\n"; std::cout << "b after splice:"; for (int x : b) std::cout << " " << x; std::cout << "\n"; }
Program output
a after splice: 5 9 b after splice: 10 2 20

before — list a = {5, 2, 9}, list b = {10, 20}. src points at node 2 in a; dst points at node 20 in b. splice moves node 2 (highlighted) into b, just before 20 — re-linked, never copied

close the gap in list a: node5.next → node9 AND node9.prev → node5. list a is now {5, 9}. Node 2 now belongs to no list — the same car, just uncoupled (src still points at it, iterators stay valid)

link node 2 in before 20: node10.next → node2, node2.next → node20 — a constant number of writes, O(1). after — list a = {5, 9}, list b = {10, 2, 20}; both stay fully doubly-linked. One 2 total — it moved, it was not copied

#include <iostream> #include <list> #include <algorithm> int main() { std::list<int> a = {5, 2, 9, 1}; std::list<int> b = {10, 20}; // first refers to node 2 (INCLUDED); last refers to node 1 (EXCLUDED) auto first = std::find(a.begin(), a.end(), 2); auto last = std::find(a.begin(), a.end(), 1); // EXPECT: the half-open range [first, last) = nodes 2 and 9 moves to end of b // after the call: a = {5, 1}, b = {10, 20, 2, 9} (moved, not copied) b.splice(b.end(), a, first, last); std::cout << "a after splice:"; for (int x : a) std::cout << " " << x; std::cout << "\n"; std::cout << "b after splice:"; for (int x : b) std::cout << " " << x; std::cout << "\n"; }
Program output
a after splice: 5 1 b after splice: 10 20 2 9

before — list a = {5, 2, 9, 1}, list b = {10, 20}. HALF-OPEN range [first, last): first = node 2 is INCLUDED; last = node 1 is the STOP marker and is EXCLUDED (greyed — it stays in a). So only nodes 2 and 9 move

close the gap in list a: node5.next → node1 AND node1.prev → node5. list a is now {5, 1} — node 1 (last) stayed. The 2⇄9 segment travels as ONE unit, internal link never touched (that is why splice is O(1) regardless of range length)

link the segment after 20: node20.next → node2, node9.next → end of b. after — list a = {5, 1}, list b = {10, 20, 2, 9}. Only the boundary pointers changed — moving 2 nodes costs the same as moving 1 (O(1) regardless of range length)

▸Key Idea

Generic STL algorithms like std::sort require random-access iterators, which std::list cannot provide (no O(1) index). list instead ships its own member sort(), reverse(), and unique(). list::sort uses merge sort — O(n log n) with no element copies, only pointer rewrites — so it is as efficient as possible for a node-based structure. unique() removes consecutive duplicates in O(n); always sort first so equal elements are adjacent.

#include <iostream>
#include <list>
int main() {
    std::list<int> lst = {5, 2, 9, 1, 7};
    lst.sort();
    std::cout << "sorted:";
    for (int x : lst) std::cout << " " << x;
    std::cout << "\n";
}
✓ Compiled
Program output
sorted: 1 2 5 7 9
#include <iostream> #include <list> int main() { std::list<int> lst = {5, 2, 9, 1, 7}; lst.reverse(); std::cout << "reversed:"; for (int x : lst) std::cout << " " << x; std::cout << "\n"; }
Program output
reversed: 7 1 9 2 5

before — list = {5, 2, 9, 1, 7}. the chain before reverse() — head is node 5

after — list = {7, 1, 9, 2, 5}. reverse() only flipped each node prev/next — the same 5 node objects, no element copied or moved; still a fully doubly-linked list

#include <iostream>
#include <list>
int main() {
    // unique removes consecutive duplicates -- sort first
    std::list<int> lst = {5, 5, 2, 9, 9, 1, 7, 7};
    lst.sort();
    lst.unique();
    std::cout << "sorted + unique:";
    for (int x : lst) std::cout << " " << x;
    std::cout << "\n";
}

Program output

▸Key Idea

A list iterator is a pointer to a separately-allocated node — insert and erase of other nodes never move it, so it stays valid. A vector iterator is an offset into a contiguous block — any push_back that exceeds capacity triggers reallocation, which moves the whole array and leaves every saved iterator dangling. AddressSanitizer catches the use-after-free.

#include <iostream> #include <list> #include <algorithm> int main() { std::list<int> lst = {5, 2, 9, 1, 7}; // store an iterator to the node holding 9 auto it = std::find(lst.begin(), lst.end(), 9); // insert 100 more nodes -- no allocation affects existing nodes for (int i = 0; i < 100; ++i) lst.push_back(i); // iterator still valid: points to the same node std::cout << "iterator still valid: " << *it << "\n"; }
Program output
iterator still valid: 9

before — list = {5, 2, 9, 1, 7}. it points to the node holding 9 — a separately allocated node with its own address

the 100 new nodes were allocated separately and linked at the tail. node 9 never moved — it still points to the same node object, so it stays valid

#include <iostream>
#include <vector>
int main() {
    std::vector<int> v = {5, 2, 9, 1, 7};
    // store an iterator (pointer into contiguous memory)
    auto it = v.begin() + 2;
    // push_back past capacity reallocates the whole array
    for (int i = 0; i < 100; ++i) v.push_back(i);
    // iterator is now dangling -- ASan catches heap-use-after-free
    std::cout << "dangling iterator: " << *it << "\n";
}
