Pointers & References (basic)

Main Takeaway

A reference is an alias — a second name for an existing object, fixed at birth and never null. A pointer is a variable that holds an address: it can be null, can be reseated, and must be dereferenced with * to reach its target. Both are indirection, and indirection is only valid while the thing it points at is alive — outlive that and you have undefined behavior.

▸Key Idea

A reference is an alias: a second name for an existing variable, bound at birth and never null, never reseated. A pointer is a variable that holds an address: it can be null, can be pointed somewhere new, and must be dereferenced with * to reach its target. Where const sits also matters: "pointer to const" freezes the pointee (you can still move the pointer), while a "const pointer" freezes the pointer (you can still write through it).

#include <iostream>
#include <cstdio>
int main() {
    int x = 42;
    // r is just another name for x — an alias, fixed for life
    int& r = x;
    // writing through the alias changes x itself
    r = 100;
    // a reference has no storage of its own: &r IS &x — one box, two names
    printf("PTRDATA: type=ref ref_addr=%p target_addr=%p target_val=%d\n",
           (void*)&r, (void*)&x, x);
    std::cout << "x = " << x << "\n";
    std::cout << "r = " << r << "\n";
}

#include <iostream>
#include <cstdio>
int main() {
    int x = 42;
    // p is a variable holding the ADDRESS of x
    int* p = &x;
    // dereference with * to reach the pointee, then write
    *p = 100;
    // p has its OWN storage (&p) holding x's address (&x) — two boxes
    printf("PTRDATA: type=raw ptr_addr=%p target_addr=%p target_val=%d\n",
           (void*)&p, (void*)p, *p);
    std::cout << "x = " << x << "\n";
    std::cout << "*p = " << *p << "\n";
    // a pointer can be reseated to point at nothing
    p = nullptr;
    std::cout << "p is null? " << (p == nullptr) << "\n";
}

Key Idea

The same glyphs & and * do two opposite jobs depending on where they appear. In a DECLARATION they are type-modifiers: "int&" builds a reference type and "int*" builds a pointer type. In an EXPRESSION they are operators acting on values: & takes the address of an object, and * dereferences a pointer to reach the object it points at. Reading code correctly means asking first: am I declaring a type, or computing with a value?

▸Key Idea

A by-value parameter is a private copy in the callee's frame, so writing to it cannot touch the caller's variable. Only indirection lets a function reach back and mutate the original: pass a pointer and the callee writes through *p, or pass a reference and the callee writes through the alias directly. A reference reads cleaner and cannot be null; a pointer advertises "may be null, may be reseated". This example is about the mechanism — Module 4 is about which one to choose.

#include <iostream>
// x is a COPY — changes stay inside this frame
void tryToSet(int x) {
    x = 100;
}
int main() {
    int n = 42;
    tryToSet(n);
    std::cout << "n = " << n << "\n";
}

#include <iostream>
#include <cstdio>
// p holds n's address — *p reaches the caller's variable
void setThroughPtr(int* p) {
    *p = 100;
    // p has its own box (&p) holding n's address; *p reached back to main
    printf("PTRDATA: type=raw ptr_addr=%p target_addr=%p target_val=%d\n",
           (void*)&p, (void*)p, *p);

Key Idea

nullptr has its own type (std::nullptr_t) that converts to any pointer but not to an integer, so it resolves overloads to the pointer version and reads unambiguously. The legacy spellings are integers in disguise: 0 is literally the int zero and picks an int overload, while NULL is a macro (often the compiler's __null) that is convertible to BOTH int and pointer — ambiguous enough here that the call will not even compile. Always spell a null pointer nullptr.

▸Key Idea

This is the most common reference misconception. Once bound, a reference names its target for life: assigning to the reference does NOT rebind it to a new object — it writes the new value THROUGH the reference into the original target. A pointer behaves the opposite way: assigning a new address to a pointer redirects the pointer itself, leaving the old target untouched. Predict each output before you reveal it.

#include <iostream>
#include <cstdio>
int main() {
    int a = 1;
    int b = 2;
    // r is bound to a for life
    int& r = a;
    // this does NOT point r at b — it copies b's value INTO a
    r = b;
    std::cout << "a = " << a << "\n";
    std::cout << "b = " << b << "\n";
    b = 99;
    // r still names a, so changing b does not touch r
    std::cout << "r = " << r << "\n";
    // r never rebinds: &r IS &a for the whole scope — one box, two names
    printf("PTRDATA: type=ref ref_addr=%p target_addr=%p target_val=%d\n",
           (void*)&r, (void*)&a, r);
}

#include <iostream>
#include <cstdio>
int main() {
    int a = 1;
    int b = 2;
    int* p = &a;
    // reseat p to point at b — a is left untouched
    p = &b;
    std::cout << "a = " << a << "\n";
    std::cout << "*p = " << *p << "\n";
    b = 99;
    // p now follows b
    std::cout << "*p = " << *p << "\n";
    // p was reseated: its own box (&p) now holds &b, so *p follows b
    printf("PTRDATA: type=raw ptr_addr=%p target_addr=%p target_val=%d\n",
           (void*)&p, (void*)p, *p);
}

▸Key Idea

Indirection is only valid while the thing it points at is alive. Three classic ways to violate that, each caught at runtime by AddressSanitizer rather than argued on a slide: reading through a pointer AFTER its heap object was deleted (heap-use-after-free); returning a reference to a local variable whose stack frame is gone the moment the function returns (stack-use-after-return); and dereferencing a null pointer that points at nothing (SEGV). The rule: never let a pointer or reference outlive its target.

#include <iostream>
#include <cstdio>
int main() {
    // the heap int is alive when we read it, and freed afterward — safe
    int* p = new int(42);
    // p holds the address of a LIVE heap int — safe to read through
    printf("PTRDATA: type=raw ptr_addr=%p target_addr=%p target_val=%d\n",
           (void*)&p, (void*)p, *p);
    std::cout << "*p = " << *p << "\n";
    delete p;
}
