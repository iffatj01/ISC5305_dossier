Module 10 — Modernization lab handout

Module 10 Lab — Modernizing a legacy C++03 kernel

You are given two genuine numerical kernels from John Burkardt’s C++ library (MIT-licensed, unedited): euler.cpp (Euler’s method) and rk4.cpp (Runge–Kutta 4). Both solve ODE systems; both are written in a 2003-era C++ style. Your job is to modernize rk4.cpp by hand while keeping it correct.

What “correct” means: a tolerance, not a byte-match

The harness runs a kernel on the harmonic oscillator y'' = -y, whose exact solution is a circle in phase space (energy conserved). It prints how far rk4’s final answer is from that exact solution:

max abs error:  4.033e-08

Your modernized rk4 is correct if it still prints max abs error below 1e-6 against the analytic solution. That is the gate — the same tolerance rule the course uses everywhere for floating point (relative error small, not bits equal).

g++ -std=c++20 -Wall run_rk4.cpp rk4.cpp -o run_rk4 && ./run_rk4
# read the 'max abs error' line: below 1e-6 = correct

Why not “don’t change a single digit”?

For the moves in this lab you will usually see every digit unchanged — but that is not the definition of correct, and relying on it will bite you later:

  • Reordering a sum changes the last bits. Floating-point addition is not associative. std::accumulate folds strictly left-to-right, so it matches a plain loop — but std::reduce (or any execution-policy/parallel version) is allowed to reassociate, and then the last digits move. Still correct; a byte-diff would wrongly call it broken.
  • A “nicer” constant changes the bits. Writing acos(-1) (or M_PI) for π gives a different bit pattern than a literal — again correct, again not byte-identical.

So judge by the tolerance, not the bytes. In this kernel there is no sum to reorder and no irrational constant, which is why the digits happen to stay put for Stages 1–3. Recognizing that boundary is part of the lesson.

The worked example: euler

Compare euler.cpp (before) with euler_modern.cpp (after). Every move you need for rk4 appears there in miniature. Note what changed — and what did not: the function’s signature is identical, so the harness links either version. Modernize the internals; preserve the interface.

Your task: rk4, in explicit stages

Do these in order. Re-build and re-check the tolerance after each stage.

  • Stage 1 — RAII buffers. Replace the eight new double[m] / delete[] pairs (f0..f3, u0..u3) with std::vector<double>. Pass .data() to the callback. When you are done there should be no new and no delete in the file.
  • Stage 2 — loops. Use int loop variables declared at the loop, not file-top. Honest limit: the flat 2-D indexing y[i+j*m] and the outer time-stepping loop do not map onto a range-for — the algorithm stays index-based there. Recognizing where modernization does not apply is part of the skill. (Range-for fits when you iterate a whole container; it does not fit a strided view into a flat array.)
  • Stage 3 — casts and namespace. Replace ( double ) ( n ) with static_cast<double>( n ). Remove the file-scope using namespace std; and qualify any std names you use.
  • Stretch (optional) — the callback. The raw function-pointer parameter can become a template parameter or std::function. If you try it, keep the answer within tolerance. (The shipped answer key keeps the C-style signature so one harness links every version.)

Want to go further? See TIERS.md for the full ladder: std::span views over the borrowed output buffer (euler_span.cpp), and a fully templated kernel that picks its precision at the call site (rk4_generic.hpp).

Honesty note

You may have been told legacy modernization means “add nullptr.” Not here: neither kernel uses NULL or a null pointer, so there is nothing to convert. Don’t invent one. The real targets above are enough.

What “done” looks like

  • No new / delete in rk4.cpp.
  • No file-scope using namespace std;.
  • static_cast instead of the C-style cast.
  • ./run_rk4 still prints max abs error below 1e-6.
