Slide 1 — One prompt, real replies

The prompt, sent verbatim — and nothing else:

Write a C++ function double trap_integrate(double f(double), double a, double b, int n) that computes the integral of f from a to b using the trapezoidal rule with n intervals.

Provenance: This code is genuine, unedited AI output. The prompt above was sent verbatim to local models over the Ollama API on 2026-07-23. Six replies were collected (3× ornith:9b, 3× gemma4:e4b) and the two shown were selected for teaching value; the selection and the full tally are disclosed in the course repository. The code was copied byte-for-byte from each reply’s code fence — nothing was edited, added, or removed.

Slide 2 — Example A: review this code

#include <cmath>

/**
 * Computes the integral of f over [a, b] using the trapezoidal rule with n intervals.
 * 
 * @param f   function to integrate
 * @param a   lower bound
 * @param b   upper bound
 * @param n   number of subintervals (must be > 0)
 * @return approximated integral value
 */
double trap_integrate(double (*f)(double), double a, double b, int n) {
    if (n <= 0) {
        throw std::invalid_argument("Number of intervals must be positive");
    }

    const double h = (b - a) / static_cast<double>(n);
    double result = 0.5 * (f(a) + f(b));

    for (int i = 1; i < n; ++i) {
        result += f(a + i * h);
    }

    return result * h;
}

(ornith:9b, 2026-07-23, reply 1 of 3 — complete and unedited.)

Slide 5 — What every reviewer missed

  • The best-looking reply of all six — and the only one that does not compile.
  • Missing #include <stdexcept>: the throw it proudly documents cannot even be named.
  • Nothing in the reply tests anything — the doc comment claims “must be > 0”; no code checks the claim.
  • Rule zero, before the five checklist categories: the compiler is the first reviewer. Trust nothing you haven’t built.

Slide 6 — Example B: this one compiles (excerpt)

double trap_integrate(std::function<double(double)> f, 
                       double a, 
                       double b, 
                       int n) {

    // Handle invalid input for n
    if (n <= 0) {
        return 0.0; // Or throw an exception if strict error checking is required
    }

    // Calculate the width of each interval (h or delta x)
    double h = (b - a) / n;

    // Initialize the sum with the endpoint values: f(a) + f(b)
    double total_sum = f(a) + f(b);

    // Loop through the interior points (i=1 to i=n-1).
    for (int i = 1; i < n; ++i) {
        double x_i = a + i * h;
        total_sum += 2.0 * f(x_i);
    }

    return (h / 2.0) * total_sum;
}

(gemma4:e4b, 2026-07-23, reply 1 of 3 — function excerpt, lightly elided comments; full 91-line file in the kit.)

Slide 7 — Finding 1: it isn’t the function we asked for

signature
The prompt double trap_integrate(double f(double), double a, double b, int n)
The reply double trap_integrate(std::function<double(double)> f, double a, double b, int n)

Checklist category: spec alignment.

Slide 8 — Finding 2: the silent sentinel

    if (n <= 0) {
        return 0.0; // Or throw an exception if strict error checking is required
    }

Measured behavior (captured probes): n=0 -> 0 · n=-5 -> 0 — exit code 0, no error, no message.

Checklist category: correctness / edge cases.

Slide 9 — Finding 3: is this a bug?

Measured: trap_integrate(lin, 2.0, 0.0, 10) → -6 (integrating “backwards”, a > b).

All six replies did the same. None documents it. None tests it.

Checklist category: correctness / edge cases — discussion.

Slide 10 — Findings 4 & 5: noise, and a demo is not a test

  • Nearly every line narrates itself — // Calculate the width of each interval — while the ONE comment that matters (the sentinel) hides a correctness decision in plain sight. Category: style — review is signal-to-noise.
  • The reply’s main prints two integrals next to their expected values in comments. Nothing fails if they’re wrong. Category: testability — a demonstration you eyeball is not a test that can fail.

Slide 11 — Same prompt. Same day. Two different failures.
